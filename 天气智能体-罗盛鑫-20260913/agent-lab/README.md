# 智能体交互模型

一个**可复用**的 agent 骨架：把"用户 ↔ 智能体 ↔ 工具"三者之间到底怎么交互，
定成一套状态 + 一套事件，然后让网页前端把这个过程实时画出来。

和 `weather-agent-web/` 的区别：那边是一个写死的天气助手，
这边是**模型和工具解耦**——工具是注册进来的，加一个工具不改一行循环代码。

---

## 一、交互模型是什么

一次交互 = **一条事件流**。四个概念撑起全部：

### 1. 状态（Phase）

```
idle ──▶ observe ──▶ think ──▶ act ──┐
  ▲                                  │
  └─────── done ◀────────────────────┘   （think 决定不再调工具 → done）
                                         （重试耗尽 / 超轮数 → failed）
                                         （用户点停止 → stopped）
```

| 状态 | 在干什么 |
|---|---|
| `idle` | 等用户输入 |
| `observe` | 把用户的话、或上一轮工具的结果放进上下文 |
| `think` | 等模型产出（流式文本增量，或"我要调工具"） |
| `act` | 执行工具，把结果写回上下文 |
| `done` | 模型不再要工具，收工 |
| `stopped` | 用户点了停止，本轮跑到一半收手 |
| `failed` | 真失败 |

注意 `think → act → think` 可以转好几圈，这就是 ReAct。
**"转几圈"由模型自己决定**，人只负责设上限（`max_turns`，默认 6）。

### 2. 事件（Event）

后端只发事件，前端只画事件。**加功能 = 加事件类型，不用改渲染逻辑。**

| 事件 | 载荷 | 何时发 |
|---|---|---|
| `session` | 模型、工具清单 | 会话建立 |
| `state` | `{phase, turn}` | 每次状态迁移 |
| `token` | 一段文本 | think 阶段流式增量 |
| `tool_call` | `{name, args, call_id}` | 模型决定调工具 |
| `tool_result` | `{name, ok, result, elapsed, call_id}` | 工具返回 |
| `stopped` | `{turns, tool_calls, tokens, elapsed}` | 被用户中断，已收手 |
| `error` | 错误信息 | 重试耗尽 / 超轮数 |
| `done` | `{turns, tool_calls, tokens, elapsed}` | 正常结束 |
| `__end__` | — | 流结束哨兵 |

传输用 SSE（`text/event-stream`），一行一个 `data: {...}`。

### 3. 循环（Loop）

`AgentSession.run()` 是个生成器，每产出一个事件就 yield，调用方立刻能推给前端。
所以浏览器看到的是**逐 token、逐步**，不是等 20 秒哗一下全出来。

### 4. 工具（Tool）

```python
@registry.register
def get_weather(city: str) -> str:
    """查询指定城市的实时天气。

    Args:
        city: 城市名称，如 昆明、北京
    """
    ...
```

JSON Schema **从类型注解和 docstring 自动推导**，不手抄第二份。
改签名就是改契约，不会出现"说明和代码不一致"。

## 二、三条设计规矩

**1. 错误当数据。**
工具不存在、参数写错、网络超时、工具内部抛异常——全都不抛，
返回 `"错误：……"` 字符串塞回上下文。模型看到错误会自己换参数、换工具、或降级回答。
只有"重试 N 次仍失败""超过最大轮数"才算真失败（发 `error` 事件）。

**2. 模型看不到 UI。**
`agent_core.py` 不 import 任何 FastAPI / HTML 的东西。
它只产事件，所以同一个核心既能喂浏览器，也能喂终端或 notebook。

**3. 历史可回滚。**
一圈跑砸了，把这一轮写进去的半成品消息弹掉。
否则下一条 user 消息会带着没有对应 `tool_calls` 的孤儿 `tool` 消息去请求——OpenAI 会直接 400。

---

## 三、会话历史存在哪

**内存态不够用**：原先历史只活在 Python 进程里，刷新页面（前端每次生成新的随机
`session_id`）或重启服务，记录就没了。现在改成落盘：

```
.sessions/<session_id>.json     # 一个会话一个文件，内容就是 messages 数组
```

- **`session_id` 存 localStorage**（键名 `agentlab.session_id`）——刷新还是同一个会话
- **每轮跑完写盘**，放在 `finally` 里：浏览器点"停止"、网络断了，聊过的内容也不丢
- **启动时按需读回**：服务重启后第一次请求该会话，从磁盘捞回 messages 接着聊
- **`GET /api/history`**：前端靠它把历史重画出来（工具卡片按 `tool_call_id` 配对）
- **`POST /api/reset`**：内存 + 磁盘一起删，这才是真的清空

顶栏两个按钮分工：**清空会话** = 抹掉当前会话；**新会话** = 另起一个 id，旧的还留在磁盘上。
`.sessions/` 已加进 `.gitignore`，不会进仓库。

> `session_id` 来自浏览器，直接拼进文件路径会有穿越风险
> （`../../etc/passwd`）。`safe_sid()` 只放行 `[A-Za-z0-9_-]{1,64}`，
> 其余一律换成 sha256 前 16 位，等于自动洗白。

## 四、中断与重新生成

| 动作 | 接口 | 发生什么 |
|---|---|---|
| 停止 | `POST /api/stop` | 置一个标志位，循环在下一个检查点收手 |
| 重新生成 | `POST /api/retry` | 先 `drop_last_turn()` 删掉上一轮，再拿同一个问题重跑 |

标志位在三个地方被检查：**每收到一个 token 增量**、**每个工具调用之前**、**每一轮开始**。
所以"中断思考"是真的断在生成过程中（还会主动 `close()` 掉上游连接），
不是前端假装不看——后者模型那边还在烧 token。

> **中断时必须保证历史仍然合法**，这是最容易踩的坑：
> 如果 assistant 带着 `tool_calls` 已经写进历史、但对应的 tool 结果还没补齐，
> 下一条请求会被 OpenAI 直接 400 拒掉。所以：
>
> - 断在**行动阶段**：剩下没执行的调用补一条 `（用户中断，工具未返回结果）` 占位
> - 断在**思考阶段**：保留已吐出的半截话，末尾加 `…（用户中断）`，用户看得到它说到哪
>
> 无论哪种，中断后的历史都能直接接着聊。

前端两个入口：发送中按钮变「停止」；中断或回答完之后「重新生成」可用
（它会把上一轮的 Agent 回复从界面上撤掉，再流式补上新的）。

## 五、联网查资料

两个工具，标准的"先搜后读"：

| 工具 | 干什么 |
|---|---|
| `web_search(query, max_results)` | 搜索，返回标题 + 链接 + 摘要 |
| `fetch_url(url, max_chars)` | 打开网页，把正文抓成纯文本 |

搜索后端：**配了 `TAVILY_API_KEY` 用 Tavily**（质量更好、自带答案摘要）；
没配就走 **Bing 的 RSS 输出**（`&format=rss`），不需要 key。

> 踩过的坑：Bing RSS **必须带 `mkt=zh-CN`**。不带的话它返回一堆官网首页，
> 带上才给出精确的结果页链接——同一个查询，结果质量天差地别。

`fetch_url` 里两个不能省的细节：

- **编码嗅探**：很多国内站不在 Content-Type 里带 charset，requests 会默认按
  ISO-8859-1 解码，中文全是乱码。先看 header、再看 `<meta charset>`、最后才猜。
- **SSRF 护栏**：只收 http/https，并拒绝内网 / 本机 / 保留地址
  （`file://`、`127.0.0.1`、`10.x` 全部挡掉），别让模型拿它去扫内网。
  http 链接返回 4xx 时会顺手试一次 https。

现实情况：政府站、门户站、日历站读得到；百度百科 / 知乎会 403（反爬）；
Wikipedia 在这台机器上不通。**打不开是常态**，所以系统提示词里要求
"换搜索结果里的下一条"，并且允许实在读不到正文时用摘要作答——但要标注
「这些来自搜索摘要、没能打开原文核对」。

搜索结果会带上发布日期（`2026-09-01` 这种格式，Bing 原始的
`周日, 30 8月 2026 16:22:00 GMT` 太难读），方便模型判断一条内容是不是新的。

**系统提示词里会注入今天的日期**，这条不能省：模型知识有截止日，不告诉它今天几号，
问"最近的新闻"它会去搜"2024年"，搜回来一堆过期内容。注入之后再问同样的问题，
它会自动搜"AI 新闻 2026年9月"。

> 实测对比：不注入日期时，同一个"最近 AI 新闻"的问题连续搜 12 次全是
> ai-bot.cn、Wells Fargo、Google 首页这类无关结果，最后撞到轮数上限空手而归；
> 注入日期后 3 次调用就拿到了当天的新闻日报并给出带来源的回答。

提示词还给了工具预算（大约 4~5 次调用），防止它把轮数全耗在重试上、
最后一事无成地空手回来。轮数上限相应放宽到 8。

想让新闻类搜索质量更好，就去配 `TAVILY_API_KEY`——Bing RSS 对"精确文档"类查询
（某某通知全文）表现很好，对"最近新闻"这类模糊查询只能给出一堆官网首页。

## 六、跑起来

```bash
cd KUST/agent-lab
python app.py                 # → http://localhost:8000
python app.py --port 8080
```

依赖：`fastapi uvicorn openai python-dotenv requests tavily-python`
密钥直接复用 `ch1-intro-and-toolcalling/notebooks/.env`，不用再配一份。
没配 `TAVILY_API_KEY` 也能跑，景点推荐会走内置兜底数据（页面上会标注）。

核心可以脱离网络自测，不花 token：

```bash
python agent_core.py          # 假 client：第 1 轮调工具，第 2 轮给答案
```

## 七、前端

`static/index.html`，单文件、无构建、无 CDN 依赖。三块：

- **对话流**：左边。工具调用渲染成可折叠卡片（名字 / 参数 / 耗时 / 结果），失败自动展开
- **状态机**：右上角。当前阶段高亮，转圈时能看到 `think → act → think` 来回跳
- **事件流**：右下角。原始事件逐条打出来——教学时这块最好用，
  学生能直接看到"原来这就是模型和工具之间的对话"

发送中按钮变「停止」→ 真中断；「重新生成」→ 撤销上一轮重跑。状态机最后一个节点会显示
中断 / 失败 / 完成。
