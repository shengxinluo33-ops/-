## rating：只有 311 本是真的，其余 7749 本是填充值

**按 rating 排序前请先看这段。**

| 来源 | 本数 | 说明 |
|---|---|---|
| 我们自己回微信读书查的推荐值 | 118 | 94.1% → 9.4 分制 |
| 协作库那批里豆瓣自带的 | 193 | `rating` 字段原本就有 |
| **真评分小计** | **311（3.9%）** | |
| 同分类均值填充 | 7749（96.1%） | **不是真实评分** |

填充规则：缺评分的书填**同分类均值**（只采纳 ≥5 分的真实评分计算——
页面上的无关数字会被正则误抓成 1.0，不参与计算）。
该分类一个真实评分都没有时，退回全局均值 7.8。

**分不清哪些是真、哪些是填充的**：填充值等于该分类的均值，会和真实评分撞值。
真要严格区分，只能看采集侧的 `score IS NULL` 记录（在 `data/novel.db` 里）。

## 其他已知的数据缺陷

- **2 个可疑的低分**：《名剑风流》1.0、《法医秦明：无声的证词》4.6。
  这两个是**页面上的无关数字被正则抓来的**（《名剑风流》不可能是 1.0 分，
  《法医秦明》也不该只有 4.6），因为回填只填空缺不覆盖已有值，所以留下来了。
  用之前建议手动清掉。
  （全表 rating < 5 的一共 3 本，第三本《你看完不敢睡，看了还想看的悬疑小说. Ⅰ》
  4.8 来自豆瓣的真实评分，**不是**误抓，不用清。）
- **作者缺失 75 本**：几乎全部来自我们自己采的那批（榜单页作者栏经常填成
  评论人或干脆空着）。协作库那批 的作者字段是完整的。
- **简介质量参差不齐**：我们自己采的那批清洗过一轮（删掉了百科页面的
  `## 目录 ## 创作背景` 结构、自媒体的 `📖【书名】💡【作者】` 模板词、
  导航条和商店信息），清洗后实在没内容的 7 本用"《XX》是XX创作的XX类小说"兜底。
  协作库那批的简介平均 137 字、质量更稳定，但**没做过同样的清洗**，
  个别条目可能残留页面元信息，建议抽查。
- **封面图 URL 不在这份 CSV 里**：`database.txt` 的表头没有封面字段，
  所以没导出。库里 **470 本**有真实封面 URL（`data/novel.db` 的
  `cover_url` 字段），需要封面可以另外提供。

## 封面的覆盖率为什么只有 5.8%

封面是按来源回填的，四路加起来 470 本（`data/novel.db` 的 `cover_url` 字段）：

| 来源 | 有封面 |
|---|---|
| 起点中文网（封面回填） | 231 |
| 微信读书（封面回填） | 152 |
| 起点中文网（采集时自带） | 71 |
| 红袖添香（采集时自带） | 16 |

回填补的主要是**起点**——这批书本来就是从起点/红袖爬出来的，
回老东家查命中率约 95%。但起点对我们 IP 有**小时级**限流，
跑到第 145 次请求左右就 403，一轮只能吃 150 本左右。

微信读书那条线**已经停手**：它的搜索页正文里挂着「请勿使用第三方插件……
将有可能导致你的账号被封禁」，而且那批网络文学在微信读书的命中率是 0%
（冷门网文和杂志期刊它压根没收录）。原因和实测数据见 `logs/fixlog.md` 第 25 条。

## 同一本书只保留一条

按 `(title, category)` 判重，重复是**更新不是堆积**：已有封面和评分不会被空值盖掉。

分类归一（54 → 22 个分类）时合并过 4 组 9 条同名冲突（《江湖》《重生》《青春》
《青梅竹马》），保留信息最全的一条、缺的字段补过来再删其余，共删 5 条。
详见 `logs/fixlog.md` 第 22 条。

## 数据怎么来的

采集自公开榜单页（Tavily 搜索 + 静态/动态解析）、起点中文网移动端、微信读书，
并合并了协作库里同组采集的 7970 本小说 CSV（`import_csv.py`）。
只取出版元数据（书名/作者/简介/封面/评分/链接），**不采章节正文**。

重新生成：

```bash
python export_csv.py            # 只扫描噪声条目，导出 novels.csv
python export_csv.py --clean    # 先删噪声条目（媒体名/杂志名/作者名）再导出
python clean_data.py --apply    # 清洗简介 + 合并重复条目（会重建向量索引）
python normalize_categories.py  # 分类归一（同类异名合并 + 非小说类归"其他"）

# 起点封面回填（--source 只挑协作库那批，见 fixlog 第 23 条）
CRAWL_MIN_DELAY=2 CRAWL_MAX_DELAY=4 \
  python qidian_source.py backfill 300 --source 起点中文网 红袖添香
```
